# FE Express plan — bounded AI-BS source reuse inventory

November 14, 2026. Read-only code inventory; **no runtime checks or tests were run for this inventory**. Private records, credentials and database contents were not opened. This document supplies planning context; development and integration setup remain paused.

| Area | Source inspected | Reuse and limits |
|---|---|---|
| Phone portal | `frontend/src/components/FEExpressPinPortal.jsx`, `WebsitePhoneLogin.jsx`; `backend/security/website_phone_access.py` | Phone/PIN, in-memory expiring session, origin/path restriction, logout and lock. This is shared portal access, not established individual driver identity, recovery or MFA. FE access does not grant administrator identity. |
| FE route access | `backend/security/fe_express_access.py`; `backend/routers/fe_express_router.py` | FE, website-session or administrator admission. Individual driver ownership restrictions were not found in the reviewed report routes. |
| Driver and shipment reports | `backend/fe_express_driver_reports.py`; `frontend/src/components/FEExpressDriverReports.jsx` | SQLite daily miles/hours/fuel/expenses, shipment dates/status, revision conflicts and weekly exports. Owner/subcontractor assumptions require review. Agreed shipment revenue is not company-driver earnings or verified payroll. |
| Paperwork | Same report sources | PDF/JPEG/PNG originals, upload UUID retry protection, SHA-256 receipts, download, grayscale packet and weekly ZIP. Current source limits: 10 MiB/file, 20 files/50 MiB/shipment. FE OCR, automatic receipt classification and explicit camera capture were not found in this scope. |
| Workspace drafts | `frontend/src/utils/feExpressWorkspace.jsx`; `backend/fe_express_workspace.py` | Explicit server saves and revisions/stale-write conflicts. Current workspace is one shared row rather than per-driver isolated state. Selected files must be uploaded before leaving. |
| Offline design references | `frontend/public/sw.js`; `frontend/src/utils/conversationOutbox.js` | Service worker fetch passes through without an offline application cache. Chat has an IndexedDB outbox with scope/revision/hash checks that may inform a new FE design; it does not implement FE offline capture. FE upload queue/background synchronization were not found. Downloaded Excel edits explicitly do not synchronize back. |
| Personal accounting | `backend/modules/accounting_router.py`; `backend/security/financial_auth.py`; `frontend/src/components/industry_suites/FinanceSuiteTab.jsx` | Owner-scoped manual income/expense, idempotency and explicit receipt matching; finance tab wraps an economics summary. Financial access requires verified administrator ownership. A FE phone token cannot simply reuse it. Driver budgeting, bank ingestion and payroll reconciliation were not found in this review. |
| Original-preserving intake | `frontend/src/utils/driveIntakeDocuments.js`; `backend/routers/document_converter_router.py`; `backend/security/document_access.py` | Working-copy utility and DOCX text conversion. Access is administrator/file-ticket scoped, not established phone-portal access or receipt OCR. |
| Native FE client | `native_studio/fe_express_service.py`, `fe_express_view.py` | Existing service-client/table surfaces may support workstation review. Their presence does not establish the new Android workflow or employer-system integration. |
| Navigation hazards | `backend/routers/fe_express_router.py`; `backend/core/fe_express_owner_operator_engine.py` | Small hardcoded list and demo corridor heuristic, including an `is_safe` field without real routing evidence. **Do not qualify this as truck GPS or reuse that field as a navigation safety guarantee.** Turn-by-turn, phone geolocation, offline maps and a complete maintained restriction dataset were not found in this bounded scope. |

Relevant existing test sources include `backend/tests/test_fe_express_driver_reports.py`, `test_fe_express_workspace.py`, `test_fe_express_pin.py` and `frontend/tests/portal-routing.test.mjs`. Their existence is not a fresh pass result.

Review priority on explicit resume: company-driver data/pay contracts; individual ownership and separate personal access; Android durability and synchronization; maintained truck-routing qualification. Preserve original stored data and adjacent owner-operator/booking features. No current backend, remote access, company system, map provider or private-document workflow was activated.

Canonical requirements: [Driver Portal and Personal Finance Plan](DRIVER_PORTAL_PERSONAL_FINANCE_PLAN.md). Source inventory is limited to the named local components and related functions, not all AI-BS history or every financial subsystem.
