## Remaining limits and next work

- Network payouts, registration/heartbeat credit and untrusted paid job admission are intentionally held. Real owned compute/payment evidence, durable payout reservations/idempotency/recovery and the approved isolated worker boundary are required before release. A secret or UI flag cannot release the current hold.
- Global host telemetry is administrative, not a per-tenant data product. Legacy hardware history remains unverified; new measured observations do not reconcile the old history. New history reads cap at500, while write-retention pruning is not implemented. Raw traffic and source backups were excluded from cloud history export.
- Physical NVML/fan enforcement was not independently exercised. Single-fan verification is request-time measured readback only; automatic and multiple-fan enforcement remain unverified. Default safety intent remains100%, without claiming that a displayed/requested percentage proves enforcement.
- Provider credential validity/revocation and any historical administrator-key exposure remain unverified. Source removal/redaction does not revoke a previously leaked credential or erase Git history. No real provider/financial/exchange acceptance was attempted.
- No exchange-held positions, protective stops, financial history reconstruction, native binary rebuild, Git commit or push is included. Four protected crypto safety/control/monetary hashes remain unchanged. Source release v5.329.74 does not establish a new native executable release.

ADR-120 decision: preserve the interfaces while containing unreconciled financial/untrusted compute dispatch; require verified administration for host diagnostics/controls and explicit evidence for UI metrics. This replaces unsafe prototype success with observable held/unavailable states under the user's fix authorization. Future activation must supply the missing evidence and regression acceptance rather than reopen the retired optimistic paths.

Evidence: `backups/network_hardening_20261030T220825Z`; frontend/adjacent and hardware agent checkpoints are referenced by the final manifest. Exact before/after copies, source diff, raw red/green output, runtime/Hosting receipts and append-prefix checks are retained. Two checkpoint-merge layout/schema assumptions were stopped, diagnosed and corrected using actual manifest schemas and original hash comparisons; no source restore or evidence deletion occurred.

Next step: retire any exposed provider/admin credentials as needed, reduce scoped type debt, and build owner-scoped verified compute/payment records plus durable dispatch recovery using offline fixtures before considering activation.
