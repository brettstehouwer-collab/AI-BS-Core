# Nsight error 1421: reproduction and qualification boundary

The qualified 4324 HUD-fit player and canonical source remain unchanged. A
separate 2a91 diagnostic build adds only bounded stderr messages before the
unchanged chapter GPU guard. Its validator checks nine runtime artifacts,
158 canonical pins, 158 isolated pins and the exact diagnostic insertion.

The uninstrumented diagnostic proof exits zero with 1,016,027 nonbackground
pixels, actual DX12 debug layer enabled, and zero errors/warnings. Under Nsight
2026.4 capture it has the same pixel count but two errors and zero warnings,
then exits one. Both are DX12 message 1421:

- `ID3D12DeviceTools1::GetApplicationSpecificDriverBlobStatus`
- `ID3D12DeviceTools1::GetApplicationSpecificDriverState`

Both messages say the device does not support application-specific driver state
and refer to CheckFeatureSupport. No references to those calls were found in
reviewed engine C++/headers. The errors occur only under injection in this
controlled comparison; an external caller stack was not captured.

The documented per-capture `--no-internal-pipeline-caches` option was tested
once and did not remove either error. Both failed runs remain preserved. No
further equivalent capture trials should run without a new supported remedy.
No error filter, debug disable, ignore-incompatibility, driver/security/global
profile change or forced process termination was used.

## Reproduction tools

Recovery Python runs `engine/tools/prepare_rtx_nsight_diagnostic.py --prepare`
only into new fixed diagnostic source/build locations. Existing outputs refuse
replacement. Configuration/build were offline VS2022 x64 Release, parallel4.
Preparation never launches the player. Its manifest is
`t/nsight_diag_build01/frozen-candidate-v01.json`.

For the prepared build, `engine/tools/qualify_rtx_nsight.py
--diagnostic-candidate --output NEW_Nsight_LH_CHILD` runs a fresh uninstrumented
baseline, then capture. Native/tool failure propagates and prevents automatic
replay. The optional `--disable-capture-pipeline-cache` requests the documented
per-capture control above; it does not weaken the native guard.

exit zero and clean release of 43 objects, with none failed/skipped. Captured
and replayed PNGs have identical bytes/hashes and Nsight image MAE zero. Both

`69fcd42c988ae58ef581525c2f0177e4ba5aa69efd09262cb67294f3cdd3203c`.

`engine/tools/replay_rtx_nsight_capture.py` admits only that exact retained

not ordinary-game FPS; its GPU-time field is unavailable (-1).

This qualifies an inspectable/replayable frame, not native debug-injection,
GPU Trace, ordinary play/performance, installed Studio or release. Retain this

publication was sent.
