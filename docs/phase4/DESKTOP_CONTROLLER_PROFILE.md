# Desktop provisioning profile candidate

October 24, 2026. `isolated_workers/windows/control/VM-DesktopGuards.ps1` adds a pure metadata validator for the preserved desktop configuration. No existing controller imports it; no hypervisor action, guest command, activation or task execution is enabled.

It pins VM `6c5a53da-ab80-4ecb-8be6-4059266f736e`, snapshot `dca55e17-086c-46f4-8cd9-aaf98154e2a5`, current child disk `7dd3e9fa-d52e-4e63-b9b8-4fa5663ffe84`, DVD `0b72ff83-f6d1-4b14-81d7-c637268365b1`, the exact v1 ISO path and the existing configuration/disk paths. An operation must explicitly require either `running` or `saved`; other states and a different observed state are rejected. VM and snapshot names are checked as additional consistency fields, alongside their fixed UUIDs.

All eight NICs, clipboard/file transfer, drag and drop, USB controllers, audio, remote display, recording, serial/parallel devices, nested virtualization, tracing and autostart remain disabled. Memory, CPU, firmware, Secure Boot, boot order, controller type/count, both storage attachments and hot-plug settings are fixed. Extra controllers/attachments or any shared-folder field are rejected. Names and folders alone do not establish containment.

The old recovery guard, setup channel and recovery entrypoint were preserved byte-for-byte. The candidate does not repurpose their operation paths or modify observed values to make an old profile pass. The old guard continues to reject the new desktop DVD. Detached v2 media is intentionally rejected by this v1 profile; a future optical-media transition must bind its actual newly registered UUID and independently verified bytes.

The 74 test cases run in Windows PowerShell 5.1 and PowerShell 7 use **synthetic VM-info data**. They start with a retained old inspection and explicitly substitute documented desktop identity values. They prove predicate behavior, not a new actual hypervisor query, worker ownership, snapshot/disk ancestry, installed runtimes, licensing, guest transport or any of the fourteen containment cases. Missing/changed critical fields, caller-state mismatch and the historical guard's rejection are covered. The absent candidate first produced a retained failing test, followed by passing results.

Before adopting this validator in a controller, require a fresh authenticated standard-worker session, a signed hypervisor binary, exact process creation/SID/session binding, an exclusive operation lease, source pins, fresh actual VM-info and filesystem/media/ancestry checks, and independent preservation on failure. Preserve the existing immutable status and frame/request freshness controls. Do not restart a stopped setup channel against a running guest or replay uncertain installation/control operations.

The desktop snapshot preserves the pre-provisioning state with an expired-license watermark. It is not a licensed accepted task base. Exact guest runtime/import/licensing output remains pending. A later accepted task image needs its own independently verified base-image identity and the complete transport, cancellation, recovery and containment evidence. Task admission remains unavailable.
