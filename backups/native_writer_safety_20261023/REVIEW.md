## Changes

Native project catalog/read/create/import/save/export now use the actual project-scoped backend. The client obtains AI_BS_ADMIN_KEY from the process environment per request; it has no embedded key, no unauthenticated fallback, and only sends to 127.0.0.1:8080 with proxy environment and redirects disabled. Network calls run on EngineBus workers, with a single in-flight operation per writer view.

Editor initialization is blank/read-only until an authenticated project read succeeds. Empty host scripts stay empty. Project selection changes only after successful read. Switching from a dirty draft first saves the departing project's content with its exact revision. Failed or uncertain saves retain the current editor and block blind retries. Typing during a save or pending read remains in the current editor. Explicit Reload Host retains the outgoing draft before replacing the editor, with confirmation when unsaved or uncertain.

Unsaved drafts receive unique UTF-8 JSON recovery copies under C:/AI-BS/saved_data/native_screenplay_recovery/<profile-fingerprint> after a one-second idle delay and before save/switch/reload, plus best-effort application quit capture. This store stays within AI-BS and is already Git-ignored. A new per-profile directory is created atomically with a protected Windows DACL granting inheritable full control only to the current token user, SYSTEM and Administrators. Existing folders are inspected and refused if their permissions differ; no existing folder ACL or ownership is changed. All existing path components are checked for junctions/symbolic links, and the resolved target must remain directly inside its intended store. This is filesystem access control, not content encryption; local administrators retain access.

Copies contain project, revision and complete text, with no API key/token. Existing recovery copies remain intact; unchanged snapshots are deduplicated only after integrity verification. A modified snapshot causes a fresh copy. Recovery storage/privacy failure blocks transitions and normal top-level window close through a narrow application event filter, even if the writer subtab is hidden. This guard runs before MainWindow shutdown stops workers. The Recovery button displays the folder and latest path; automatic recovery merging is not implemented.

Create and import are backend create-only operations; duplicate project errors preserve existing work. Native imports accept strict UTF-8 Fountain/text, structurally checked FDX XML converted to text, and selectable-text PDF extraction with a layout-loss confirmation. DTD/entity declarations including UTF16 are rejected. Sources remain unchanged. A PDF with no extracted text fails with an OCR requirement. pypdf must be included in the packaged runtime; the resumed dependency review below supersedes the initial missing-dependency observation. Native FDX import does not preserve every Final Draft layout/formatting property and remains subject to the shared backend Fountain parser's existing semantic limitations.

Exports retrieve actual PDF/FDX bytes through the backend and verify the host revision before and after generation. Fountain export reads confirmed host text. Output creation is exclusive: existing files and previous exports cannot be replaced. The disconnected call-sheet PDF action is disabled instead of claiming success.

Adaptation first requires authenticated capabilities contract create-only-v1, then submits the real multipart manuscript to /api/screenplay/adapt with force=false. It monitors actual job ID/status; it does not manufacture an adapted scene. This requires the separately staged backend adaptation hardening. Old backends lacking the contract are refused before upload. Only one job is monitored per view, and a stopped monitor can be resumed with Adaptation Status. Existing external jobs are still subject to server-side save guards.
