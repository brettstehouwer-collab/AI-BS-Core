## Implemented API and source authority

- backend/security/firebase_auth.py::firebase_admin_principal/get_admin_principal resolve stable verified subjects. Existing is_firebase_admin_token and verify_admin_credentials boolean/key interfaces remain. Cache holds only token fingerprints, expiry, allowed email and stable principal; allowlist is rechecked on cache hits. Invalid/expired/nonfinite/bool/overflow expiration or malformed SDK returns fail closed.
- backend/core/conversation_sessions.py::save_conversation/read_conversation/list_conversations stores full canonical message JSON/title with SHA256, IDs, expected revision, count and timestamp. Two private tables, conversation_heads and conversation_revisions, are created only by a valid admitted write in the existing vault transaction. BEGIN IMMEDIATE and compare-and-swap serialize writers. Independent committed readback confirms a revision before durable=True. Existing global archive rows remain unchanged. Revisions are immutable through this API; there is no pruning/delete endpoint.
- backend/routers/conversation_router.py is included by existing memory_router.py, whose /api/memory prefix produces GET /conversations/identity, GET /conversations (limit1-50 and optional before cursor), GET /conversations/{32hexID} (optional revision), and POST /conversations/{32hexID}. POST body is request_id, expected_revision, messages and title; additional owner/client fields reject. Each message must carry a unique32hex id, with the remaining finite JSON metadata retained. The owner always comes from backend credentials. No configured DB path is accepted from the client.
- List order/cursor is descending stable conversation ID, not last-edited order or a frozen multi-page snapshot. Missing tables mean empty new history only when neither private table exists; incomplete schema or missing/corrupt recorded revisions fail rather than report empty success. Errors map to403/404/409/422/503 as applicable and never return a database path. Reads do not initialize schema. Missing vault files are never created.
