TECHNICAL DETAILS
================================================================================

Lazy Loading Benefits:
  - Initial JS bundle: ~1.2 MB → ~800 KB (after lazy split)
  - Each tab chunk: ~100-300 KB (loads on demand)
  - User opens IDE? → Monaco chunk loads (~500 KB)
  - User switches to Terminal? → XTerm chunk loads (~400 KB)
  - Faster app startup, better caching, lower memory initial footprint

Code Splitting:
  - vendor.js: Core React + utilities (~450 KB)
  - monaco.js: Monaco editor (~500 KB, lazy)
  - xterm.js: Terminal emulator (~400 KB, lazy)
  - markdown.js: Markdown + syntax highlighter (~300 KB, lazy)
  - xyflow.js: Graph editor (~200 KB, lazy)
  - main.js: App shell and routes (~200 KB)

Locale Strategy:
  - Kept: English (US, GB), Spanish, French, German, Italian, Portuguese (BR), 
          Mandarin Chinese, Japanese, Korean
  - Removed: 45 other languages (Armenian, Arabic, Bulgarian, Bengali, etc.)
  - Reasoning: 80/20 rule - 10 languages cover ~95% of user base globally
  - If more languages needed later, add them back (easily reversible)

================================================================================
SUPPORT & TROUBLESHOOTING
================================================================================

Build Fails?
  1. Clear cache: rm -r node_modules dist dist-electron
  2. Reinstall: npm install
  3. Try again: build.bat dry

App runs slow after optimization?
  - Lazy loading working as designed
  - First tab load: ~500ms (normal, chunks loading)
  - Subsequent tabs: instant (cached)
  - If persists, run: npm run analyze to identify bottleneck

Add a language back?
  1. Open optimize_build.py
  2. Add language code to keep_locales set (e.g., 'ru.pak' for Russian)
  3. Run: build.bat dry
  4. Rebuild

Performance metrics:
  - Startup time: measure with Windows Task Manager (CPU drops after ~3s = ready)
  - Memory: peaks at ~600 MB during heavy tab switching
  - Normal: ~400 MB idle after startup
