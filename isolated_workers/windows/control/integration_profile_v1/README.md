# Integration observation profile v1

This module describes a separate networked integration role. It does not register
a worker, start a VM, execute guest code, expose a service or admit code execution.
The original offline profile and quarantined attempts remain unchanged.

The profile tests use synthetic metadata adapted from a retained worker query.
Their positive XML fixture disables audio and optical hot-plug in memory only.
The current VM XML is explicitly refused; no fresh native query or guest agreement
has been established. Passing fixtures do not prove live admission or containment.

Record109's exact fingerprint is retained as an observation pin. Current XML has
changed and is refused rather than automatically repinned. Review the actual
worker-owned native metadata, disk ancestry, mounted media and new fingerprint
before building a runnable integration entry.

Observed configuration includes NAT localhost reachability, an OHCI USB
controller, enabled audio input/output and optical hot-plug. OHCI is represented
only as an observation; attached host USB devices remain unverified. Audio and
hot-plug fail the current profile. Core loopback listeners must remain private.
Authentication, scoped messages, manifest I/O, network restrictions and negative
access tests are still required. The result always returns false for task,
provider, transport and containment acceptance. No scheduler consumes this profile.

Run the infrastructure tests with Windows PowerShell:

    powershell.exe -NoProfile -File C:\AI-BS\isolated_workers\windows\control\integration_profile_v1\Test-IntegrationProfile.ps1

Do not retry admission or mutate the VM based solely on these tests. Preserve
operator sessions, original disks/snapshots and prior evidence.
